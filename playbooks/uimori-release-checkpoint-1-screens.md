# Uimori 릴리스 체크포인트 1: 직접 볼 화면 체크리스트

PR #15–#55의 설명(2026-11-28 기준, 병합된 PR만)에서 "직접 확인해 주세요"로 적힌 화면과 상태를 모아 정리했어요.

## 읽기 화면

- [ ] Risu 장면의 표시 변환이 실패한 경우: 원문이 그대로 남고, 언어를 바꾸면 경고와 그 안의 사유가 함께 번역되는지 봐요. (#24)
- [ ] 번역된 장면과 번역 안 된 장면에서 이미지 자동 배치 버튼이 각각 제대로 동작하는지 봐요. (#35)
- [ ] 장면 삭제 대화상자를 다른 탭에서 이미 삭제한 장면으로 열었을 때, 일반 리비전 충돌 문구가 나오는지 봐요. (#35)

## 채팅·작성

- [ ] 채팅 변수나 고아 메모리를 두 탭에서 편집해 둘 다 저장하면, 두 번째 탭에 충돌 메시지가 뜨고 작성 중인 내용이 남는지 봐요. (#38)
- [ ] 작성창에서 프롬프트 조합을 적용한 뒤 채팅 옵션이 조합과 일치하는지 봐요. (#38)
- [ ] 채팅 메뉴와 채팅 헤더에서 채팅을 삭제할 때, 사전 요청 없이 확인창이 바로 열리는지 봐요. (#42)
- [ ] 한 탭에서 이미지를 삭제한 뒤 다른 탭에서 그 이미지 이름을 고치면, 충돌 안내와 입력한 글자가 남는지 봐요. (#42)
- [ ] 채팅 폴더 설정과 봇 기본 페르소나 대화상자에서 페르소나가 있을 때와 없을 때 각각 저장해 봐요. (#42)
- [ ] 채팅 변수와 스토리 가이드를 편집한 뒤 다른 탭에 실시간으로 반영되는지 봐요. (#45)
- [ ] 채팅 입력창에 파일 이름 없는 이미지를 붙여넣으면 칩 이름과 alt/title이 "참고 이미지"(영어 "Reference image", 일본어 参考画像)로 보이는지 봐요. (#30)

## 서재·편집기

- [ ] 서재 콘텐츠 편집기와 프롬프트 프리셋 편집기를 두 창에 열고, 한쪽에서 저장하면 깨끗한 다른 창이 구역 이동이나 스크롤 점프 없이 제자리에서 갱신되는지 봐요. (#48)
- [ ] 위 상태에서 갱신된 창에 입력하고 먼저 창에서 저장하면, 충돌 안내와 저장본 확인이 바로 뜨는지 봐요. 좁은 폰 폭과 데스크톱 모두요. (#48)
- [ ] 이전 저장본으로 복원한 직후 바로 입력해도 가짜 충돌이 나지 않는지 봐요. (#48)
- [ ] 서재 삭제 확인창을 열어 둔 채 다른 곳에서 그 항목을 저장하면, 확인했을 때 "다른 요청이 먼저 반영됐어요"가 나오고 조용히 삭제되지 않는지 봐요. (#48)
- [ ] 서재 → 봇 → 로어북에서 영어와 일본어로 "로어 추가"와 "폴더 추가" 이름("New lore", "New folder", 新しいロア, 新しいフォルダー)을 보고, 이전에 만든 항목 이름은 언어를 바꿔도 변하지 않는지 봐요. (#30)

## 프롬프트·모델 설정

- [ ] 설정 → 기본 프롬프트에서 한 창의 옵션을 바꾸고 다른 창이 따라 바뀌는지 봐요. (#48)
- [ ] 비한국어 UI에서 채팅 설정의 프롬프트 옵션 그룹과 에이전트 협업 공유 옵션을 열어 봐요. 그룹 없음 묶음의 접힘 상태가 한 번 초기화되는 것은 예상된 동작이에요. (#25)
- [ ] 같은 UI에서 Risu 토글 편집기의 그룹을 옮긴 뒤 선택 상태가 유지되는지 봐요. (#25)
- [ ] 프롬프트 → 프리셋 → 토글에서 영어와 일본어로 select 항목을 추가해, 라벨("New item" / 新しい項目)과 옵션("Option 1,Option 2" / 選択肢 1,選択肢 2)을 확인해요. (#30)
- [ ] 프롬프트 편집기 → 에이전트 협업에서 영어로 캐릭터, 로어, 커스텀 에이전트를 추가해 이름과 설명이 자연스러운지 봐요. (#33)
- [ ] Vertex 위치 비교 목록을 좁은 폭에서 열어, 짧은 코드 대신 "프로바이더에 연결하지 못했어요." 같은 문장이 "다시 시도" 버튼 옆에 잘 들어가는지 봐요. (#27)
- [ ] 응답 테스트 한 번이 실패하면 "응답에 실패했어요." 아래에 인증, 속도 제한, 시간 초과 같은 구체적 한 줄이 나오고, 원본 코드는 "오류 상세"에 남는지 봐요. (#27)

## 도우미

- [ ] 도우미 도구의 변수와 스토리 가이드 검증 실패가 통일된 오류 코드(INVALID_REQUEST)로 보이는지 봐요. (#45)
- [ ] 도우미가 변수를 바꾸지 않는 no-op 갱신을 보낼 때도 영수증 기록이 남는데, 이 재시도 동작이 의도에 맞는지 판단해 줘요. (#45)

## 삭제·충돌 안내

- [ ] 저장하고 나가기 실패 배너와 저장본 확인 실패 대화상자를 띄운 채 언어를 바꾸면 배너와 버튼 라벨이 함께 바뀌는지 봐요. (#24)
- [ ] 컨텍스트 실패 행이 옛 DB에서 온 경우(장면 인스펙터, 작업 기록, 컨텍스트 패널), 일반 문장과 "오류 상세" 안의 원문(`<pre>` 간격과 줄바꿈)이 보기 좋은지 봐요. (#27)

## 백업·가져오기

- [ ] 카드 가져오기 미리보기에서 `@@position` / `@@inject_at`이 있을 때와 알 수 없는 `@@` 지시어가 21개 이상일 때("외 N개")를, 미리보기를 연 채 언어를 바꿔 가며 봐요. (#28)
- [ ] 프리셋 가져오기 미리보기에서 지원하지 않는 블록과 `promptSettings.utilOverride`가 있을 때를 같은 방식으로 봐요. (#28)
- [ ] 프리셋 가져오기가 결과 불명으로 끝난 뒤 재시도가 409를 받으면 파일을 다시 고를 수 있는지 봐요. (#28)

## 알림·언어

- [ ] 영어와 일본어로 채팅을 복사하면 "(copy 1)" / "(コピー 1)", 다시 복사하면 "(copy 2)"가 되고, 한국어 사본 "X (사본 1)"을 영어에서 복사하면 "X (copy 1)"이 되는지 봐요. (#33)
- [ ] 프롬프트, 봇·서재 항목, 일러스트 프리셋의 제목이 최대 길이(200자 / 100자)일 때 영어와 일본어에서 복사가 저장되고 접미사가 유지되는지 봐요. (#33)
- [ ] 설정 → 사용량 → CSV 내보내기를 영어와 일본어로 받아 스프레드시트에서 13개 헤더 이름을 읽어 봐요. lang=en 성공 경로는 HTTP 수준 테스트가 없어요. (#33)

## 배포 환경

- [ ] 실제 프록시 뒤에서 다운로드와 SSE 스트림이 정상인지 봐요. 자동 검증은 loopback 합성 픽스처로만 돌렸어요. (#52)
- [ ] `UIMORI_MCP_TOKEN`을 설정했다면, Tailscale Serve 뒤에서 `Authorization`, `MCP-Protocol-Version`, `Mcp-Method` 헤더가 그대로 통과해 외부 클라이언트가 붙는지 봐요. (#49, 개발 세션 보고에서)

## 조율 세션이 덧붙인 항목 (PR 본문이 아니라 개발 세션 보고에서)

- [ ] 실행 접수 응답을 잃은 뒤 새로고침하고 확인하는 흐름에서, 작성한 요청이 남고 재시도가 한 번만 기록되는지 봐요. (#37)
- [ ] 유지보수 모드 배너와 Story UI 오류 메시지가 의도대로 보이는지 봐요. (#53)
- [ ] 협력 모델이 있는 번들을 가져올 때 미리보기의 모델 안내가 자연스러운지 봐요. (#53)
- [ ] 삭제한 봇이 붙어 있는 채팅에서 봇 정보를 여는 화면이 "삭제됨"으로 제대로 안내되는지 봐요. 운영 스냅샷 비교에서 삭제된 항목 3개의 리소스 읽기가 200에서 404로 바뀐 걸 확인했어요. (스냅샷 재생 검사)
- [ ] 아웃라인 패널에서 항목 편집과 포커스 지정을 해 보고, 도우미가 아웃라인을 바꿨을 때 변경 카드가 뜨고 턴 되돌리기로 복구되는지 봐요. (#55)
- [ ] `.chat.uimori`로 복원한 채팅(이전에 복원해 둔 것 포함)의 첫 장면이 "첫 메시지"로 보이고, 요청 말풍선·모델 이름·다시 쓰기가 붙지 않는지 데스크톱과 모바일에서 봐요. ⋯ 메뉴도 열어 봐요. (#58)
- [ ] 설정 → 프로바이더와 모델 → 모델 프리셋 → 고급 탭을 데스크톱 폭에서 열어, 평가 도구 섹션이 빠진 자리의 간격과 정렬을 봐요. 평가 도구를 켜 두었던 프리셋 2개는 이제 평가 도구 없이 요청을 보내요. (#59)
- [ ] 도우미에게 URL 없이 "이 모델 단가를 입력 $3 / 출력 $15로 넣어 줘"처럼 시켜서 저장되는지 봐요. (#59)
